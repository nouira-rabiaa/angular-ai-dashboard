# Internationalisation — UX-3A en attente de revue manuelle

## Périmètre de cette étape

Base : `e03163978d639cf225a9e42a135136d7db3616f4`, branche `feat/phase-5-support-agent` propre et synchronisée au début de l'audit. Cette livraison locale prépare seulement l'infrastructure, le header, la sidebar, les titres du navigateur et les notifications globales. **Les textes des cinq espaces métier ne sont pas encore localisés intégralement** : ce sera UX-3B, après validation manuelle Safari. Aucun commit/push n'est autorisé à ce stade.

## Choix technique et catalogues

Transloco **8.4.0**, version épinglée, déclare `@angular/core >=16.0.0` et `rxjs >=6.0.0` dans ses métadonnées npm, compatibles avec le projet Angular 19. Le mode runtime `reRenderOnLangChange` évite tout rechargement ou rebuild. Référence : [configuration officielle](https://jsverse.gitbook.io/transloco/getting-started/config-options).

`src/app/i18n/catalogs/fr.json` et `en.json` contiennent **36 clés chacun** pour l'identité, la navigation, les actions globales et erreurs. Le français est préchargé ; l'anglais est importé dynamiquement dans un chunk séparé. Pas de service de traduction externe ni d'appel IA. Le loader reste utilisable par les routes lazy futures. Transloco gère l'interpolation ; aucun libellé de comptage/pluralisation n'est nécessaire pour le shell actuel, donc aucun plugin ICU supplémentaire n'est installé.

`npm run check:i18n` vérifie les clés FR/EN, les valeurs non vides, les paramètres d'interpolation et les références statiques globales. Le contrôle est exécuté automatiquement avant le build. Une clé anglaise manquante utilise le français ; une clé absente des deux catalogues renvoie un libellé de secours compréhensible et produit un avertissement en développement, jamais la clé brute.

## Langue et persistance

`UiLanguageService` centralise le choix `fr` / `en`, les Signals et l'accès défensif à `localStorage`. Clé : `enterprise-ai-dashboard.ui-language`. Le français est le défaut, indépendamment de la langue du navigateur. Une préférence inconnue est ignorée. Un accès refusé au stockage ne bloque pas le changement en mémoire. Le chargement anglais s'effectue avant activation ; un échec garde le français et affiche un avertissement. Des requêtes de langue hors ordre ne peuvent pas écraser le dernier choix.

Un initialiseur Angular attend la préférence enregistrée avant le premier rendu de l'application. `document.documentElement.lang` suit le choix et `UiTitleStrategy` met à jour le titre du navigateur lors des changements de langue et de route. Le sélecteur natif FR/EN du header comporte un groupe nommé, des libellés localisés, un état `aria-pressed`, un focus visible et un état de chargement. Le badge de démonstration est masqué sur petit écran pour laisser de la place au sélecteur.

## Séparation des données et formatage

La bascule remplace les textes via les pipes Transloco ; elle ne recrée pas le RouterOutlet ni les composants métier. Aucun agent, document, nom, instruction, message, citation ou brouillon n'est traduit ou réécrit. Aucun header de langue n'est ajouté aux API, aucune requête RAG ou génération n'est relancée. La langue configurée de l'agent reste indépendante.

Les helpers `number`, `percent`, `currency` et `date` utilisent Intl avec `fr-FR` / `en-US`. Ils préservent les valeurs et la devise passée (USD par défaut), sans conversion. Les pourcentages prennent un ratio, par exemple `0.8`. Les dates utilisent UTC par défaut, avec options explicites possibles. Les valeurs indisponibles ont un libellé localisé. **Les formatages des routes existantes et leur LOCALE_ID ne sont pas encore migrés** ; les helpers seront raccordés en UX-3B afin de conserver les contextes et unités métier.

## Erreurs globales

`ErrorService` conserve son message existant et ajoute une présentation optionnelle `{key,params}`. L'intercepteur sélectionne cette clé frontend à partir du statut HTTP (et du cas réseau), pas du texte du serveur. Les codes HTTP, propriétés JSON et erreurs propagées aux composants ne sont pas traduits ni modifiés. Les notifications globales utilisent la clé pour se mettre à jour à chaud, sans afficher le corps libre du serveur. Un message sans clé de présentation reste inchangé pour compatibilité ; les autres affichages d'erreur de route seront traités en UX-3B.

L'erreur connue d'import du Générateur reçoit seulement une clé de présentation supplémentaire. Son layout validé, ses actions et ses validations restent inchangés. Aucun changement backend, SQLite, Groq, prompt, RAG, FinOps, authentification ou permission. Le projet reste une application locale sans authentification.

## Installation et validation manuelle

Depuis `client` : `npm ci --legacy-peer-deps`, `npm run check:i18n`, `npm test -- --runInBand`, `npm run build`. Les versions existantes du lockfile sont conservées ; seuls Transloco et ses dépendances nécessaires sont ajoutés. Jest autorise la transformation ESM du namespace `@jsverse`, sans désactiver de test.

Dans Safari, vérifier FR → EN → FR, les noms accessibles du menu mobile, le sélecteur à 375/768/1280/1440 px et la restauration après Cmd+R. Naviguer entre les cinq routes : le shell et le titre du navigateur changent, tandis que les contenus métier restent dans leur langue actuelle pour cette étape. Vérifier un brouillon de configuration et une sélection documentaire non enregistrée, puis une conversation sélectionnée : aucune perte, sauvegarde automatique ou nouvelle inférence ne doit survenir.

La validation JSDOM ne prouve pas le rendu responsive ni le comportement natif complet de Safari. En l'absence de WebDriver utilisable, aucune validation visuelle réelle n'est revendiquée. Attendre la validation manuelle avant UX-3B, puis seulement préparer les deux commits distincts demandés. Ne pas commencer 5D ni UX-4.
